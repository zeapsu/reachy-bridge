# Live logs system panel — specification

## Contract

The controller owns one `LogBroker` shared by controller records, `AppSupervisor`, and `DaemonSupervisor`. Every source has a 500-line `deque` ring and a bounded independent subscriber queue. A dedicated `ProcessLogPump` thread drains each merged text stdout/stderr pipe immediately, flushes `.reachy-logs/<source>.log`, and publishes lines without blocking the ASGI loop. Pump shutdown is joined in `asyncio.to_thread` after the child is reaped.

Sources are `controller`, `daemon`, and dynamically discovered app ids. Status is one of `live`, `stopped`, `offline`, `unavailable`, or `empty`. Managed daemon/app launches truncate and reset their source before starting; adopted processes are never claimed and report unavailable capture with persisted tail when available. Controller logs use one root logging handler installed for lifespan and removed before teardown.

`GET /api/logs/sources` returns `{sources: [{id, status, pid, app_status, external}]}`. `GET /api/logs/stream?source=<exact-id>` rejects unknown ids and returns no-cache SSE. Each connection starts with one `log-reset` containing status and at most 200 lines (ring or bounded file tail), batches `log-lines` at 4 Hz or 32 lines, emits `source-status` on transitions, and sends a 15-second keepalive. All persisted tail reads run in `asyncio.to_thread`.

## UI behavior

The system instrument contains accessible stats/logs tabs and two tabpanels. Stats markup remains behaviorally unchanged. Logs uses a native source select, text-safe span nodes inside a capped 500-line `<pre role=log aria-live=off>`, implicit follow, and one `follow live` button when the user scrolls away. No search, filtering, download, pause, or clear controls are included.

Stats and logs streams are lazy and mutually exclusive: only the selected panel's stream exists while the document is visible. Visibility teardown closes all conditional streams; re-entry opens exactly one. Telemetry and audio retain their existing lifecycle. Untrusted log content is rendered with `textContent` only.

## Verification

Focused tests cover broker replay/drop/status/thread-safe fanout, pump merged output/file flush/burst shutdown, supervisors and adopted status, controller handler lifecycle, source validation, SSE events, and the served browser tab/source/visibility lifecycle. Hardware-only Jetson checks remain a post-deploy checklist.
