First published nightly of reachy-bridge. It runs a Reachy Mini Lite from a Jetson Orin Nano
(JetPack 7) with no laptop attached. This is a prerelease for testing on the owner's robot. It
is not ready for general use yet.

## What's in it

**Runtime and install**
- The upstream `reachy-mini` daemon (1.12.0, locked in `uv.lock`) runs as an always-on user
  service on `127.0.0.1:8000`. Every patch to the daemon goes through one seam (`upstream.py`),
  and `reachy-bridge-runtime --check` checks it against the installed daemon (#157, #147).
- `deploy/install.sh` installs the runtime, controller and systemd user units, plus the
  `reachy-bridge` command (`status`, `start`/`stop`/`restart`, `logs`, `serve`, `pair`, `devices`) (#157, #172).
- `reachy-bridge devices` numbers paired devices and revokes them by number (#176).
- Kinematics switch and a gravity-compensation fix (#153).
- Power and wake calls run one at a time (#147).

**Controller and dashboard**
- A Rust controller on `127.0.0.1:7861` serves the React dashboard it embeds (#154).
- The dashboard is redesigned with Robot, Apps and System tabs, and has a bottom bar on phones (#174).
- A live 3D view of the robot sits next to the camera. When the robot is off, the stage shows
  a clear off state, and the robot rises in when it powers on (#173, #180, #182).
- Manual drive: two thumb pads plus antenna sliders over a drive WebSocket. The session
  survives quick switches between controls and retries a refused start. On phones 390x844 and
  larger, the drive pane and the whole robot fit on one screen; smaller screens such as 375x667
  still need a short scroll (#170, #178, #179, #187).
- Expressions, telemetry, camera, audio and logs. The expression list now recovers from a
  dropped connection during load (#181).
- Power off stops any running move before the sleep move. Enabling the motors or gravity
  compensation waits for a power change in progress, and enabling is refused while the robot
  is off or powering off (#175, #185).
- After an app stop turns the motors back on to return home, the daemon now reports them as on.
  Before, going limp during an app and then stopping it made power off skip the sleep move and
  leave the head up (#189).

**Apps**
- Hugging Face apps run through the daemon. Their own UIs open inside the dashboard and are
  proxied over HTTPS on :8043 when published on the tailnet with `reachy-bridge serve on`
  (#145, #162, #168).
- Get apps: browse Pollen's featured apps and all Reachy Mini apps on Hugging Face Spaces from
  the Apps tab, then install, update or remove them. Sign in to Hugging Face (over the HTTPS
  tailnet address) to install your own private Spaces. The robot's daemon keeps the token on
  the device, and the dashboard never shows it again (#190).
- Tap an app's row to see who made it and a link to its Space page. Catalog rows also show
  likes and when the Space last changed (#193, #194).
- Installed apps use their Space's title, the same name the catalog shows. Private Spaces keep
  their repo name (#195).

**Access**
- Optional controller login for LAN access, alongside tailnet access through
  `reachy-bridge serve` (#169).
- Without LAN login, the controller API answers only under a loopback, localhost or tailnet
  name, which blocks DNS-rebinding pages (#190).
- The controller refuses a non-loopback `CONTROLLER_HOST` unless LAN login is on. App UIs
  behind the proxy can't set the dashboard's login cookies or make cross-site writes or WebSocket
  connections through it (#185).
- The System panel shows the detected platform (#140, #167).

**CI and releases**
- CI runs python, rust-web, shell and sim integration jobs on arm64 (#161, #166).
- Release tags publish the source archive, `uv.lock` and `SHA256SUMS`. Build attestations
  start once the repository is public.

`v0.1.0-rc1` was tagged but never published, because the release job failed on a build
attestation that GitHub doesn't offer for private repositories. The release job now skips it
while the repository is private (#191). This release adds the Apps catalog on top of rc1.

## Install or upgrade

Switch the robot off first. `reachy-bridge robot-power` (or `deploy/reachy-bridge robot-power`
before the first install) should print `off`. Then run this in
the checkout on the device:

```bash
git fetch --tags && git checkout v0.1.0-rc2
deploy/install.sh
```

To roll back, check out the commit you were on before and run `deploy/install.sh` again with the robot off. Rolling back from a version with the mic mixer, first run `~/.local/share/reachy-bridge/.venv/bin/reachy-bridge-mic-mixer --untee`, or apps will hear silence; `reachy-bridge deploy <tag>` does this for you.

## Known issues

- App UIs embedded in the dashboard may break for apps that send `X-Frame-Options`.

Report problems as issues labeled `regression` that name `v0.1.0-rc2`. The stable `v0.1.0`
follows after 7 days with no open regression.
