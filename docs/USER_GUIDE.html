Section 01

What you're holding

The Reachy Mini Lite is the tethered desktop robot: it plugs into your Mac over USB and borrows your computer's brain. This workspace turns that hardware into something programmable.

Because the robot was still being assembled while this was built, everything was developed simulation-first against a headless MuJoCo physics daemon. The crucial property: the same code runs unchanged on the real robot — you only swap which daemon is running.

The Lite carries a 120° / 12 MP camera, a 5 W speaker, and 2 microphones (it lacks the wireless version's onboard compute, battery, Wi-Fi, and IMU). That hardware set is exactly what the four custom apps were designed around.

Everything lives here ~/reachy/ — a single git repository. Custom apps under apps/, the SDK clone and reference apps are kept alongside for study.

The daemon, explained

The daemon is a background service that owns the low-level link to the robot (or the simulator). Your scripts never talk to motors directly — they connect to the daemon via ReachyMini(). It must be running for anything to move.

Mac caveat The MuJoCo GUI viewer won't launch on this Apple-Silicon Mac (a known limitation). The sim therefore runs headless — full physics, no on-screen window. That's all the custom apps need to be verified.
Section 03

Quick start

Three terminals' worth of ritual. The daemon stays running in its own window; your scripts run in another.

1 — Start the daemon

# Simulation (no robot needed) — headless on this Mac ~/reachy/.venv/bin/python -m reachy_mini.daemon.app.main --sim --headless # Real Reachy Mini Lite (USB) reachy-mini-daemon

Verify it's alive: open localhost:8000/docs (API) or localhost:8000 (dashboard).

2 — Smoke test the SDK

# wiggles the antennas — proves code → daemon → robot works ~/reachy/.venv/bin/python ~/reachy/hello.py

3 — The control primitives

  • goto_target(...) — move smoothly to a pose over a duration (blocking, choreographed).
  • set_target(head=, antennas=) — push a target every tick in a real-time loop (~50 Hz).
  • create_head_pose(yaw=, pitch=, roll=) — build a head pose from angles.
Section 04

The four custom apps

Each is a proper ReachyMiniApp — it appears in the dashboard, can be started/stopped by the daemon, and is publishable to Hugging Face later. Run any of them directly with python -m <name>.main while the daemon is up.

A sim-verified

reachy_dance

reachy_dance.main:ReachyDance

Beat-synced choreography: head yaw/pitch/roll and antennas driven by sine/phase math at musical frequencies, plus a gentle idle breathing behavior as a reusable building block. All motion clamped to safe limits.

cd apps/reachy_dance && …python -m reachy_dance.main
B sim-verifiedinput on HW

reachy_simon

reachy_simon.main:ReachySimon

A Simon-style memory game with no screen — the robot plays a growing sequence of antenna flicks and head turns; you repeat it using the antennas as buttons. Win/lose animations included. Auto-mode lets it demo headless.

cd apps/reachy_simon && …python -m reachy_simon.main
C sim-verifiedcamera on HW

reachy_lookat

reachy_lookat.main:ReachyLookat

A "look at me" control loop: grabs camera frames, runs OpenCV Haar-cascade face detection, and smoothly steers the head toward the largest face (EMA smoothing, clamped angles). Degrades gracefully to neutral when no camera is present.

cd apps/reachy_lookat && …python -m reachy_lookat.main
D mic/speaker on HW

reachy_chat

reachy_chat.main:ReachyChat

A full voice conversation: microphone → local speech-to-text → an LLM over OpenRouter → local text-to-speech → speaker, with expressive motion while it talks. See the next section for the pipeline.

cd apps/reachy_chat && …python -m reachy_chat.main
Tip You can also install/start apps from the dashboard, or via REST: POST /api/apps/start-app/<name> and POST /api/apps/stop-current-app. Only one app runs at a time.
Section 05

Inside the voice pipeline

The stock conversation template was built on OpenAI's Realtime API, which OpenRouter cannot proxy. So reachy_chat was refactored into a discrete, turn-based pipeline where only the LLM step uses the network (your OpenRouter credits) and both speech ends run locally — no extra API keys.

Configuration

Copy the example env file and drop in your key. The default model is set; override it if you like.

cd ~/reachy/apps/reachy_chat cp .env.example .env # .env OPENROUTER_API_KEY=sk-or-...your key... OPENROUTER_MODEL=deepseek/deepseek-v4-flash # default; any OpenRouter slug works
  • STT — faster-whisper (base.en, ~200 MB, auto-downloads to ~/.cache/huggingface/ on first run, then cached). Loads lazily, not at import.
  • LLM — OpenAI-compatible client pointed at https://openrouter.ai/api/v1, bounded 10-message history, default deepseek/deepseek-v4-flash.
  • TTS — pyttsx3 using macOS system voices (offline, no download).
  • Fallbacks — silent on STT miss, an apology line on LLM timeout, skipped audio on TTS failure. It won't crash mid-conversation.
Want a cloud voice? Both speech ends are local by choice (keeps everything on OpenRouter credits). Swap faster-whisper or pyttsx3 for a cloud STT/TTS later if you prefer higher quality — only the handler in src/reachy_chat/openrouter_chat.py changes.
Section 06

Imported reference programs

Learning material that came with the setup — clones and one-click installs to read and run.

  • SDK + examples — ~/reachy/reachy_mini/ (the pollen-robotics/reachy_mini repo). Read AGENTS.md and the skills/ guides; the examples/ folder has runnable scripts (goto_interpolation_playground.py is a good first one).
  • Community apps — Radio, Simon, and Hand Tracker are installed in the daemon (great patterns for antenna interaction, no-GUI games, and camera control loops).
  • Conversation app — ~/reachy/reachy_mini_conversation_app/, the upstream reference that informed reachy_chat.
Building your own Always scaffold with the CLI — never hand-create folders: reachy-mini-app-assistant create <name> ~/reachy/apps (add --template conversation for voice apps). Validate with reachy-mini-app-assistant check <path>.
Section 07

Going to hardware

No code changes. Just change the daemon.

# Stop the sim daemon, plug in the Lite over USB, then: reachy-mini-daemon # Everything else is identical: cd ~/reachy/apps/reachy_dance && ~/reachy/.venv/bin/python -m reachy_dance.main

What activates automatically once the robot's sensors are live:

  • reachy_dance — already complete; now moves real servos.
  • reachy_simon — the antenna/head input half becomes playable.
  • reachy_lookat — the camera feeds real frames; face tracking comes alive.
  • reachy_chat — set OPENROUTER_API_KEY in .env; the mic/speaker drive the conversation (first run downloads the Whisper model).
